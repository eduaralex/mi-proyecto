📘 Guía Completa de Git & GitHub Control de versiones profesional

Git es el sistema de control de versiones más usado del mundo. Te permite guardar "instantáneas" de tu proyecto, colaborar sin miedo y viajar en el tiempo entre cambios.

✅ Ventajas clave

📜

Historial completo

Cada cambio queda registrado: quién, cuándo y por qué. Puedes volver a cualquier versión anterior.

👥

Trabajo en equipo

Varios desarrolladores pueden trabajar en paralelo sin pisarse. Las ramas y merges son súper eficientes.

☁️

Respaldo en la nube

GitHub, GitLab o Bitbucket guardan tu código de forma segura. Accede desde cualquier PC.

🐙

Ramas (branches)

Experimenta sin miedo: crea ramas para nuevas funcionalidades, haz pruebas y fusiónalas cuando estén listas.

⚡

Rendimiento local

La mayoría de operaciones son locales (no requieren internet) y son muy rápidas.

🔍

Depuración

Comandos como git blame o git bisect te ayudan a encontrar el origen de errores.

🌿 Trabajo con ramas (branches)

Las ramas te permiten desarrollar funcionalidades aisladas sin afectar la versión estable (normalmente master/main).

ComandoDescripción
git branchLista las ramas locales. La actual aparece con *
git branch nueva-ramaCrea una nueva rama
git checkout nombre-ramaCambia a esa rama
git checkout -b ramaCrea y cambia a la nueva rama en un paso
git merge ramaFusiona la rama indicada en la rama actual
git branch -d ramaElimina una rama (solo si ya se fusionó)
# Ejemplo práctico de ramas
git checkout -b feature/login
# ... haces cambios, commits ...
git checkout master
git merge feature/login
git push origin master

💥 Cómo resolver conflictos

Un conflicto ocurre cuando dos ramas modifican la misma línea del mismo archivo. Git te pide que decidas manualmente qué versión conservar.

<<<<<<< HEAD
Cambio hecho en la rama master
=======
Cambio hecho en la rama feature-1
>>>>>>> feature-1
🔧 Resolución típica:
1. Abre el archivo conflictivo.
2. Elimina las marcas <<<<<<<, =======, >>>>>>>.
3. Deja el código final que quieras.
4. Guarda, haz git add archivo y luego git commit -m "resolver conflicto".

🔄 Flujo diario (el ciclo de vida)

1. git pull origin master # bajar últimos cambios del equipo
2. # ... editas archivos, programas ...
3. git add . # preparar cambios
4. git commit -m "feat: nueva funcionalidad"
5. git push origin master # compartir tu trabajo
⚠️ Error común: Hacer git init dentro de C:\Users\tu_usuario. Eso intenta versionar toda tu PC. Siempre crea una carpeta dedicada (mkdir proyecto && cd proyecto && git init).

🐙 GitHub: Issues y Pull Requests

Issues son tareas, errores o mejoras. Pull Requests (PR) son propuestas de cambios que se fusionan mediante revisión.

  • Crear un Issue: en GitHub → pestaña "Issues" → New issue → describir y asignar número (ej: #1).
  • Crear un PR relacionado: creas una rama, haces commits, luego push y en GitHub pulsas "Pull request" → en el cuerpo escribes Closes #1.
  • Si el PR se fusiona (merge), el Issue se cierra automáticamente.
📌 Ejemplo de PR que cierra un Issue:
Título: "Implementar autenticación"
Descripción: "Closes #12 - Agrega login con JWT"
